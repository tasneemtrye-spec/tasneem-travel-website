## استضافة Cloudflare Pages
تم التحقق من إعدادات المشروعين عبر Cloudflare API:

1. المشروع الأساسي: اسم المشروع `tasneem-travel`، والنطاق `https://tasneem-travel.pages.dev`، وفرع الإنتاج `main`.
2. المشروع الثانوي: اسم المشروع `tasneem`، والنطاق `https://tasneem-travel-preview.pages.dev`، وفرع الإنتاج `main` أيضاً.

المشروع الثانوي ليس مجرد معاينة مؤقتة؛ فهو مشروع Pages مستقل وله نشر إنتاجي مرتبط بـ `main`. لذلك يجب التعامل معه كاستضافة إنتاجية مكررة إلى أن يقرر المالك خلاف ذلك. لا تحذف المشروع الثانوي ولا تغيّر إعداداته أو نطاقه ضمن أعمال التدقيق الحالية.

النطاق الأساسي المعتمد حالياً في ملفات SEO هو `https://tasneem-travel.pages.dev`. أي توحيد نهائي للنطاقات أو تعديل Cloudflare production branch يحتاج مراجعة وموافقة منفصلة.

## قواعد العمل الآمن
1. لا تبدأ مشروعاً جديداً ولا تستبدل المستودع الحالي.
2. ابدأ كل تغيير من أحدث `main` في فرع مستقل.
3. لا تكتب مباشرة على `main`؛ استخدم Pull Request مع مراجعة الملفات والاختبارات.
4. لا تحذف مشاريع الاستضافة أو الحسابات الخارجية.
5. لا تنشر إلى الإنتاج ولا تغيّر إعدادات الإنتاج دون موافقة منفصلة.
6. لا تنسخ مفاتيح سرية أو أسراراً إلى GitHub أو الواجهة أو المحادثة.
7. طابق كود الخدمات المنشورة مع مصدر GitHub قبل أي نشر جديد.

## وظائف Supabase المنشورة
آخر مراجعة للإصدارات المنشورة:
- `submit-booking`: الإصدار 12، يستخدم Resend لإشعارات البريد.
- `track-booking`: الإصدار 2.
- `fetch-travel-news`: الإصدار 3، والتحقق من JWT مفعّل.
- وظائف Gmail OAuth ما زالت منشورة؛ لا تحذفها لمجرد أن تكامل Gmail متوقف من واجهة الإدارة.

تمت مزامنة مصدري `submit-booking` و`track-booking` مع النسخ المنشورة، وإضافة مصدر `fetch-travel-news` إلى المستودع في Pull Request منفصل غير مدمج حتى الآن. لم تتم إعادة نشر أي وظيفة خلال التدقيق.

## الأخبار الرسمية
- جدول الأخبار: `public.travel_news`.
- جدول المصادر: `public.travel_news_sources`.
- مجدول `pg_cron` نشط كل 15 دقيقة.
- آخر نتائج مفصلة تمت مراجعتها: قطاع الحج والعمرة – اليمن ووزارة النقل – اليمن أعادا عناصر قابلة للحفظ؛ وكالة الأنباء السعودية أعادت صفر نتائج؛ وزارة الحج والعمرة السعودية أعادت HTTP 403؛ ووزارة الأوقاف والإرشاد – اليمن أعادت صفر نتائج في آخر دورة مفصلة.
- نجاح طلب المجدول لا يعني نجاح كل مصدر؛ يجب مراجعة استجابة الوظيفة لكل مصدر.
- توجد مصادر رسمية سعودية ويمنية مسجلة، لكن التغطية السعودية لم تُثبت بعد في جدول الأخبار. لا تعرض خبراً على أنه رسمي دون التحقق من رابط المصدر الأصلي.

## لوحة الإدارة والخصوصية
- المسار: `/admin.html`.
- تعتمد حماية بيانات العملاء على RLS والتحقق من صلاحيات المدير داخل قاعدة البيانات، لا على إخفاء رابط الإدارة.
- لا ترسل طلب حجز تجريبياً إلى قاعدة الإنتاج دون موافقة صريحة، ولا تستخدم بيانات عملاء حقيقية للاختبارات.
- لا ترسل كلمات المرور أو أرقام الجوازات أو صور الوثائق عبر نموذج الاستفسار.

## ملاحظات الأمان
آخر مراجعة Security Advisor أظهرت:
- `travel_news_sources`: RLS مفعّل ولا توجد سياسات؛ الوصول المقصود عبر الخدمة الخلفية فقط. أبقِ ذلك مغلقاً للزوار ما لم يتم تصميم سياسة وصول مقصودة.
- `publish_assistant_knowledge(integer)`: دالة SECURITY DEFINER قابلة للاستدعاء من authenticated، لكن جسمها يتحقق من `is_tasneem_admin()` قبل النشر. راجع هذا الحاجز عند أي تعديل للدالة.
- حماية كلمات المرور المسرّبة في Supabase Auth غير مفعّلة؛ يوصى بمراجعة تفعيلها من إعدادات Auth.
- لا تغيّر RLS أو صلاحيات الدوال أو إعدادات Auth دون مراجعة واختبار منفصلين.

- لا تغيّر النطاق canonical أو روابط Sitemap قبل اعتماد نطاق الإنتاج النهائي.

- تم تأكيد نجاح مراحل بناء ونشر المعاينة لـ Pull Request #19 على مشروعي Pages.
